# AINotes 技术方案

> 创建：2026-11-02。管理方式参考既有阅读库；针对本库的原创学习笔记用途做适配。设计变化在末尾追加决策记录。

## 目标

将分散的学习提问转成可回查的知识结构，既能按章节学习，也能按问题、术语、公式直接复习。使用普通 Markdown 文件与 Git 版本历史，在 GitHub 和支持相应语法的本地阅读器中阅读。

重点维护四条关系：问题对应解释，解释对应公式和例子，结论对应来源，更新对应历史记录。

## 沿用的管理方式

| 机制 | 在本库中的用途 |
| --- | --- |
| README 首页 | 集中列出全部笔记、日期、标签和阅读入口 |
| wiki/index.md | 按“能回答什么问题”组织检索，一句话说明用途 |
| wiki/log.md | 只追加学习和维护变更，保留更正轨迹 |
| AGENTS.md | 让不同 AI 工具遵守同一套内容与提交约定 |
| 证据层与编译层分开 | 原始材料保真保存；学习笔记可修订；来源仅链接时明确不宣称全文归档 |
| 校验后原子提交 | 正文、首页、索引与日志保持一致，使用预期分支版本防止覆盖并发修改 |

本库当前内容是对话学习后的原创整理，不是文章抓取库。因此先维护 wiki 正文，有实际原始材料归档需求时再建 sources，有媒体时再建 assets；不复制其他库的文章、安装脚本、全局技能或私人环境配置。

## 内容与检索策略

1. 按知识依赖组织正文：基础概念、内部计算、完整流程、应用、QA 与速查。
2. 同一主题优先修订已有章节；独立主题形成后再新增笔记，并保留相互引用。
3. 术语先解释角色，再给例子、公式及容易混淆的边界。示例数值与真实模型披露分别标注。
4. 每篇都有类型、来源、创建与更新日期、标签；出处链接保留版本与核验日期。
5. 查询先读 index，再读正文；小规模检索使用目录、章节深链和本地 `rg`，按实际需求再评估检索工具。

## 格式与兼容

正文使用 GitHub 风格 Markdown，公式使用 LaTeX，流程图使用 Mermaid。每张图围绕一个关系组织；数字比较用表格，避免把精确数据画成难以维护的装饰图。

章节采用显式锚点，迁移正文时更新内部链接。旧文件保留阅读入口，不复制整篇正文，不计为新笔记；已有目录链接仍可进入当前正文。

## 校验与提交

运行 `python3 scripts/lint.py`，检查 Markdown 文件的本地相对链接、显式锚点、表格列数、代码块和公式块闭合、笔记元信息、README 与实际内容计数一致性。

该脚本只验证仓库内结构，不联网验证外链，不证明公式含义正确或来源事实可靠。内容核对和新增来源核验在提交前另行完成。

提交时以最新远端分支为基础，构建仅包含本次修改的 tree/commit，再条件更新分支。发生版本变化先读取并合并，不强推。推送后读取实际远端文件并核对。

## 演进原则

当前只有一篇知识正文，先用首页、索引与日志管理。达到 20 篇且某主题至少 3 篇时再评估 topics；有实际检索需求时再评估概念页或搜索系统。保持目录增长与内容增长一致。
